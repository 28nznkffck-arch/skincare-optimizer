# スキンケア最適化ラボ — 試作 v0.8.5

予算・肌悩み・手間から基礎化粧品の組み合わせを提案する静的Webアプリ。登録120品。数量限定品と日焼け止めは対象外。

現在の登録：花王グループ106品（ビオレ21、キュレル27、ニベア9、ソフィーナ iP8、SOFINA BASIC＋2、suisai10、DEW29）、その他14品。

## 実装済み

- 月額予算（**1,000〜15,000円、100円刻み**）、15項目の肌悩み、悩みごとの優先度（最優先・気になる・軽く気になる）を指定
- 初回表示時は肌悩み未選択。選択すると提案を開始し、肌悩みだけの「選択をクリア」にも対応
- 肌質（乾燥・脂性・混合・普通・不明）、敏感肌、好みの使用感（さっぱり・しっとり・とてもしっとり）を指定
- お手入れの手間（手軽に・こだわらない・しっかり）を指定。コストは月予算の上限制約として扱い、採点には混ぜない
- 成分の優先・必須指定
- 必須カテゴリ（洗顔、保湿）と任意カテゴリ（化粧水、美容液）を組み合わせて探索
- 79商品の中から、通常画面・デバッグの首位候補探索を全件ソート不要の高速モードで実施。デバッグでの予算不足判定は最小必要月額を厳密に探索
- 手軽さの評価は追加ステップへの小さな負担として扱い、化粧水の一律除外を避ける
- 商品単位で固定・除外。合わなかった理由をブラウザ内に保存
- 1品だけ入れ替え、月額差額と組み合わせ全体の適合改善を比較。**通常月予算に追加予算を足した上限内で、現在より評価が高い1品交換だけを表示**。数字の評価点は利用者向け画面には出さず、検証画面だけで確認できる。候補がなければ空欄の理由を表示。固定品は入れ替え不可。変更後は拡張予算つきの手動選択と表示して自動選定へ戻せる
- おすすめを複数保存。保存した組み合わせごとに名称・月予算・各商品の購入価格・推定使用回数・1日使用回数を編集して月額と予算残額を再計算
- 全商品DBの価格・使用量のデバッグ画面を別ウィンドウで開く。検索・カテゴリ絞り込み・25件ずつのページ表示に対応。1回の使用量（mL/g）を編集すると内容量から1本の使用回数を再計算できる
- **2つのドラッグストア通販の税込価格をJAN一致で45/79商品に登録**（2026-11-06〜13調査）。マツキヨココカラオンライン59件＋ツルハグループe-shop6件。ツルハのサイト内JAN検索では2026年10月発売のソフィーナiP深層化粧液（4901301472762）・深層美容乳液（4901301472793）が未掲載だったため、単一店舗への全面切替は実施しない。数量限定品・日焼け止めはカタログから除外
- 一般利用者には使用量未確認の表示を**「（仮推定）」**に短縮。サイト下部に、同品目・同容量単位の2商品以上の1回量平均、参考不足時の旧来仮回数という試算方法を明記。デバッグ画面には詳しい根拠を残す
- **29商品に使用量の根拠を追加**。23商品にはメーカー・販売店記載の**使い切り期間**から、基準使用頻度で逆算した「約何回分」を登録（イハダ化粧水・乳液のメーカー掲載期間を含む）。品質の**使用期限**とは別。残りは使用量の目安（プッシュ・直径）のみ確認できる場合を分離。使い切り期間の確認がない商品は、同品目・同容量単位で根拠のある商品が2件以上あれば**1回量の算術平均を仮採用**、なければ従来の仮回数を維持
- デバッグ画面に現在の自動選定・**項目ごとの採点内訳**・各商品の**採用／不採用理由**を表示。特定商品を必ず採用して組み合わせ全体を再計算し、点数差・月額差・採用時の商品一覧を比較できる。**予算超過時にも採点を実行**する。予算内に組み直せても、元の組み合わせから**1品だけ交換すると予算超過する場合は、その直接交換の点数も別枠で表示**。予算内に候補がないときは費用最小の参考例を表示する
- デバッグ画面で商品ごとの肌悩み別の仮スコア、メーカー公式情報の確認段階、確認済み有効成分、配合濃度の登録有無を閲覧できる
- メーカー公式の情報確認に対する小さな加点を導入。効能の強さとは混ぜず、選定される商品数を増やす誘因にならないよう平均確認レベルを利用
- 注意事項はサイトの下部へ集約
- 選定条件・共通商品補正・保存した組み合わせを `localStorage` に保持（バックエンドへの送信なし）。保存プランは共通補正から独立しており、選定条件リセットでも消えない

## データの区分（重要）

| データ | 状態 |
| --- | --- |
| 商品名、内容量、メーカーの商品URL | 公式サイトで照合済み |
| JAN | メーカー・小売サイトで確認したコードを登録。イハダの2商品も2026年発売版と照合済み |
| 主要成分、製品用途の概要 | 公式サイトから要点を抜粋。全成分ではない |
| 価格 | `data/pricing.json` にJAN一致のマツキヨココカラオンライン42件とツルハ3件の税込販売価格65件を登録。購入日や店舗による変動あり。数量限定品・日焼け止めは登録対象外 |
| 1本あたり使用回数 | `data/usage.json` に**使い切り期間**（例：朝夜使用3か月）と基準頻度のある23件を逆算登録。使い切り期間がない商品は、**同品目・同単位**に2件以上の根拠付き参考例があれば、`内容量÷使用回数` で求めた1回量の平均から仮算出。参考例が不足する場合のみ `demoUses` の従来の仮回数を使用。逆算値も平均値も実測値ではない。これらは品質保証上の「使用期限」ではない |
| 1日使用頻度 | 現行値はユーザーが変更できる計算前提。メーカーが想定する頻度と異なることがある |
| 肌悩みへのスコア | アルゴリズムの仮の重み。実際の効果や安全性の予測ではない |
| 敏感肌向け・使用感タグ | 初期カタログの暫定タグ。個人の刺激や使用感を保証しない |
| `evidence.activeIngredients` | メーカー公式で有効成分表示を確認できたものだけ登録。単なる主要成分リストとは別 |
| `evidence.concentrations` | 成分名・数値・単位・公開出典URLが揃った場合のみ登録。**不明値を0%と扱わない** |

肌悩みの15項目はUIで選べます。悩みの名称は「シミ」「そばかす」とし、「予防」を悩み名に含めません。花王の薬用商品を含む追加SKUについて「シワ改善」「乾燥による小じわ対策」「シミ・そばかす予防」「皮脂・角栓洗浄」「ハリ感」の効能・用途を区別して仮スコアを付与しました。ただし**スコアは商品間の比較用に手動で定めた仮値**です。特に「乾燥による小じわを目立たなくする」は医薬部外品の「シワ改善」とは区別し、後者の点数を与えていません。赤み・色ムラなど、登録に足る判断根拠のない項目は未採点と表示します。

「シミ」「そばかす」の肌悩み向けに登録した薬用美白製品の効能は、主にメラニン生成を抑えて**新しいシミ・そばかすを防ぐもの**です。既存のシミを消す効能と混同せず、製品説明の具体的な予防表現は維持します。シミだけを選んだ際、洗顔料にシミへの点数がなくても、必須の洗顔カテゴリから別の適合条件で自然に選ばれます。

メーカーが処方を更新する場合があるため、将来は処方版・出典確認日・全成分データをそれぞれ保持し、変更検知と再検証が必要です。Amazon/@cosmeのスクレイピングは行っていません。

### デバッグ画面の使い方と判定原則

1. メイン画面で肌悩み・予算・肌質などの条件を設定し、「商品DB・使用量を検証」を開く。
2. 上部の「最良候補の採点内訳を見る」で、各悩みへの適合スコア・手間コスト・肌質・使用感・情報公開加点の計算を確認する。
3. 商品を検索し「この商品の採否理由を検証」を押す。最良候補と、その商品を固定したときの最良候補を再探索して比較する。除外設定・他商品の固定・予算超過も別の理由として表示する。**予算内に収まらなくても点数は計算**し、元の候補からその商品へ1品交換したときの予算外の参考例を表示する。予算内の組み合わせ自体がない場合は、予算を外して求めた費用最小の参考例と比較する。いずれも予算内の推奨商品として採用したわけではない。
4. デバッグ画面の価格・1回の量・使用回数を変更すると、メイン画面の自動選定でも新しい月額が使われる。1回の量と使用回数はどちらかを変更すると他方を内容量から逆算する。保存済みの組み合わせは別の独立した記録なので勝手に変更されない。

情報公開の確認レベルは `0:公式情報の登録なし` / `1:メーカー公式製品情報を確認` / `2:公式の有効成分名を確認` / `3:公式の配合量数値と出典を確認`。`evidence.officialSource: true` はメーカー公式出典の確認後にのみ設定する。今回追加した15商品には、公式の医薬部外品有効成分（該当商品のみ）を登録。ミノンや極潤ヒアルロン液などの**化粧品の保湿成分は医薬部外品の有効成分として記録しない**。濃度数値は公式の根拠を確認できないため、登録していない。**「未調査」「未登録」は「配合なし」「非公表」と同一視しない。**

情報公開のボーナスは採点上限が1.05点（1商品あたりの確認レベルの平均 × 0.35）という小さい補助点。肌悩みや処方の適合性・製品の効果を示すものではなく、公式情報が後日登録された場合はスコアが変化しうる。予算は適合点数ではなく必須の上限制約として別管理する。

## 商品データの更新

編集するデータは `catalog/` の3つのCSVです。ExcelなどではUTF-8のCSVとして開き、JAN列を文字列として取り込んでください。各表と公開用データでは、商品を13桁のJANで識別します。組み合わせ保存・固定・除外・補正も同じJANを使います。

| 操作 | 編集する箇所 |
| --- | --- |
| 追加 | 商品マスターにJANの行を作り、価格表と点数表にも同じJANを入れる |
| 商品情報・使用量の変更 | 商品マスターの該当セルを更新 |
| 価格更新 | 価格表の同じJAN・販売店の行で税込価格・URL・確認日を更新。別の販売店は行を追加 |
| 点数更新 | 点数表の該当セルを更新。空欄は未採点、0は採点済みの0点 |
| 掲載終了 | 商品マスターの掲載状態を「掲載終了」に変更。保存済みの組み合わせでは商品と保存時の費用を引き続き表示 |

リニューアルでJANが変わったときは、新しいJANを追加し、旧商品は必要に応じて掲載終了にします。誤登録を完全に削除する場合は、3つの表から該当JANの行を取り除きます。

価格表は1 JAN・1販売店につき1行です。複数の掲載価格がある場合はマツキヨココカラ、ツルハ、ウエルシアの順で採用します。「マツキヨ」「ツルハ」も入力できます。販売店で税込価格を確認できた商品の試算価格は空欄で構いません。

主要成分と有効成分は `|` で区切ります。該当しない欄や未確認の欄は空欄で、真偽を記入する欄は `true` または `false` です。「洗顔料なしで提案」の `false` は、洗顔料を含む組み合わせで提案する意味です。使用回数は使い切り日数と基準回数、または個包装の回数から算出できます。回数の根拠がなければ試算用の「1本の仮使用回数」を入力します。

編集後に `npm run catalog:build` を実行すると、JANの桁・チェックディジット、重複、別表との対応、点数範囲などを検証して `dist/data/` を生成します。`npm test` で表と公開データの一致および計算を確認し、CSVと生成されたJSONを同じコミットに含めます。

## ローカル確認

Node.jsとPython 3がある環境で `npm test`。静的配信は `npx serve dist` 等の任意のHTTPサーバーで可能です。`file://` 直接起動だとJSONの読み込みが制限されるブラウザがあります。

GitHub Pagesでは、`main` ブランチの `/ (root)` を公開元に設定してください。リポジトリ直下の `index.html` が `dist/` に転送し、アプリを表示します。Pagesの公開設定自体は別途有効化が必要です。
