# スキンケア最適化ラボ — 試作 v0.1

予算・肌悩み・手間から、基礎化粧品の組み合わせを提案する静的Webアプリです。花王グループの公式商品ページで存在・容量・主要成分を確認できた15商品を初期登録しています。

## 実装済み

- 月額予算、毛穴・くすみ・乾燥、手軽さ・バランス・コスパを指定
- 成分の優先・必須指定
- 必須カテゴリ（洗顔、保湿、UV）と任意カテゴリ（化粧水、美容液）を組み合わせて探索
- 手軽さの評価は追加ステップへの小さな負担として扱い、化粧水の一律除外を避ける
- 商品単位で固定・除外。合わなかった理由をブラウザ内に保存
- 1品だけ入れ替え、月額差額を100円単位などで比較
- 商品の購入価格・推定使用回数・1日使用回数を編集して月額を再計算
- 個人設定を `localStorage` に保持（バックエンドへの送信なし）

## データの区分（重要）

| データ | 状態 |
| --- | --- |
| 商品名、JAN、内容量、メーカーの商品URL | 公式サイトで照合済み |
| 主要成分、製品用途の概要 | 公式サイトから要点を抜粋。全成分ではない |
| 価格、1本あたり使用回数、1日使用頻度 | **試作上の仮値**。現行の販売価格・メーカー推奨回数ではない |
| 肌悩みへのスコア | アルゴリズムの仮の重み。実際の効果や安全性の予測ではない |

メーカーが処方を更新する場合があるため、将来は処方版・出典確認日・全成分データをそれぞれ保持し、変更検知と再検証が必要です。Amazon/@cosmeのスクレイピングは行っていません。

## 構成

```
dist/
  index.html
  styles.css
  app.js                # UI・状態管理
  optimizer.js          # データと独立した選定・費用計算
  data/products.json    # 商品データベース（別ファイル）
tests/
  optimizer.test.mjs
```

商品を増やすには `dist/data/products.json` の `products` 配列へレコードを追加します。`id` は一意、`category` は `cleanser / toner / serum / moisturizer / sunscreen` のいずれかです。`sourceUrl` は必須、`demoPrice` と `demoUses` は正式データ取得まで仮値として扱います。

## ローカル確認

Node.jsがある環境で `npm test`。静的配信は `npx serve dist` 等の任意のHTTPサーバーで可能です。`file://` 直接起動だとJSONの読み込みが制限されるブラウザがあります。

## 次の段階

1. 商品データの全成分と有効成分を構造化、版管理
2. 使用量の公式記述と実測値を分離、推定根拠を表示
3. 商品・処方・販売SKUを分離して詰め替え、容量違いに対応
4. 本体/詰め替えの初回価格、維持費、購入時期を分けて表示
5. 適合スコアを根拠付きのルールで見直し、表示上も過剰な精度を主張しない
6. 許可された価格情報取得手段を使い、Amazon等の購入先を接続

個人向けの比較検討ツールであり、皮膚疾患の診断・治療を目的とするものではありません。
