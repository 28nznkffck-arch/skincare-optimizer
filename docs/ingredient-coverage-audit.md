## 保存形式

各DBの `products.csv` に「配合成分」「配合成分の原文」「配合成分の確認状況」「配合成分の出典URL」「配合成分の確認日」「配合成分の出典種別」を保存。各DBの `ingredient-sources.json` には、JAN、商品URL、原文、全成分配列、出典URL・種別、確認日、取得元ハッシュ、抽出箇所を記録する。通常はHTMLのハッシュで、Webのテキスト取得を使用した6品には `captureMethod: web-text` を明記する。

成分名の並びは区切りとレイアウト空白・注釈記号を整理する。原文は整理前の表示を保存する。原本の自動取得用補助スクリプトは `scripts/collect_ingredient_sources.py`（lxmlが必要）。取得結果は人が商品・種類・JANとの対応を確認してから登録する。定期的な自動再取得は行わない。

## 選択・表示・検証

成分選択は登録後の配合成分を参照する。女性1363項目・男性548項目。成分索引1511項目中205項目は用途解説済みで、残りは表示出典と用途確認中の案内を掲載する。解説が未作成でもDB登録や選択から外さない。商品カードの「配合成分」を開くと全一覧、原文、出典を確認できる。

`npm run ingredients:check` は全成分配列の項目・順序、原文、出典、確認日を比較する。新規JAN、商品URL変更、未確認から確認済みへの不整合も検出する。未解説の仮の名前が欠落した場合にも失敗する回帰テストを含める。この検証は保存済み原本との一致を確認するもので、将来の処方変更や抽出そのものの誤りまで自動保証するものではない。

価格、容量、使用量、有効成分の採点根拠、肌悩み点の元表は変更していない。成分指定と種類数加点の入力は全成分になるため、提案結果が変わる場合がある。探索と採点の式は維持する。
